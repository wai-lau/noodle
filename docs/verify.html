verify a noodle poll

Runs entirely here, on GitHub's servers — the noodle server can't touch this page. It checks the page your browser actually received against the public source at github.com/wai-lau/noodle. Nothing you paste leaves your browser except hash lookups to GitHub.

  1. Open your poll's vote page. Press F12 → Network tab → reload the page.
  2. Click the top request (the document, named like your poll slug) → Response tab.
  3. Select all of it, copy, and paste below. Then Check.

Use the Network Response, not view-source: — view-source re-fetches the page, and a hostile server could answer that second request differently from the one that actually ran. The Network response is the bytes that ran.




  

  

    what this proves — and what it doesn't
    
It proves, for the page you pasted: every script is the public code (a sha384 the browser
    refuses to run unless the bytes match), no inline script or event handler can run, and nothing the page loads can
    leave the site — so that visit cannot leak your key. Do it each visit; a server can't fool a check you
    actually run.

    
It does not prove the public code is safe. "Matches the repo" only means the server served the repo's code.
    You are trusting that the repo itself
    is honest (and GitHub, and your browser). To trust that, read the code that touches your key — chiefly
    web/noodle-e2e.js, noodle-vote.js, noodle-claim.js,
    noodle-commit.js, noodle-keystore.js — and re-read them when they change.

    
The passphrase key-derivation runs in a Web Worker. SRI can't pin a new Worker(),
    so noodle-kdf.js (which SRI does pin) fetches the worker and its Argon2, checks them against a
    hard-coded sha384, and runs them from a Blob of exactly those bytes — a mismatch stops the derive.
    The 'wasm-unsafe-eval' in the policy is for that worker's WebAssembly only; it does not permit
    eval() or inline script, so nothing injected can still run. If you audit the repo, check that the
    sha384 in noodle-kdf.js matches noodle-kdf-worker.js and the vendored
    hash-wasm.
